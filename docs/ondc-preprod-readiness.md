# Pipeline 04H — external readiness (not registered)
Reviewed 2026-11-26. Official registry instructions mark staging retired; preprod subscription requires approved FQDN, SSL, portal profile and environment whitelisting. Latest Pramaan notice directs QA/compliance to Protocol Workbench. Use https://portal.ondc.org and https://workbench.ondc.tech/; confirm available RET10 seller version and flows, student/organization eligibility, whether a free managed hostname is accepted, and zero-cost preprod access before enrolling. Never invent business credentials. The existing Render static hostname is only a candidate and cannot serve a dynamic on_subscribe callback by itself. No external registry calls are made.
## Run
`node ondc/preflight.mjs` — offline, ephemeral Ed25519 raw public key and X25519 ASN.1 DER public key checks; site verification signature over literal request UUID, tampering rejection and shared secret agreement. No keys emitted or persisted. This does not implement actual registry AES challenge, actual registration, or production credentials.
`node ondc/preflight.mjs --https` — optional HEAD to existing public website only, no redirects, 8-second timeout. TLS/public website reachability is not ONDC connectivity. Does not verify OCSP or callback routing.
`node --test tests/ondc-onboarding.test.mjs` — eight offline tests. Full npm test picks up the file automatically. package.json deliberately untouched to preserve local Vite patch. 
## Stop gates
1. Written confirmation of free preprod eligibility and acceptable candidate host from ONDC; approved legal identity/profile and whitelisted subscriber. Do not purchase a domain or create paid resources without approval.
2. Choose same-host HTTPS dynamic callback infrastructure (verify free-tier limits). Keep verification file and callback out of public site until approved. Generate/store actual keys securely on approved infrastructure; never paste private keys into chat/GitHub.
3. Implement and test actual on_subscribe challenge against official reference, site verification deployment, subscribe schema and signed registry lookup; match approved subscriber ID, domain, city, seller type and key IDs. ACK alone is not successful registration; independent lookup must confirm the record.
4. Complete durable external buyer/order identity, idempotency, outbox and fail-closed ingress; validate actual RET10 schemas and flow versions in Workbench. The local fixture payloads and LOCAL_* codes are not official protocol compliance.
5. Test independent buyer discovery, order confirmation, shared stock, manager transitions and cancel, correlate official logs and order ID; no real transactions. Confirm no spending and no regression before activation.
